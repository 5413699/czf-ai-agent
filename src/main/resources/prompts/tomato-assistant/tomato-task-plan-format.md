# 番茄任务计划结构化输出要求

请根据基础系统提示词中的任务拆解规则，生成结构化的番茄任务计划。

# 总体要求

1. 任务计划必须围绕用户本次输入的目标生成。
2. 每个微任务只能包含一个主要目标。
3. 每个微任务必须能够在 1～2 个番茄钟内完成。
4. 当前一个番茄钟的时长为 {pomodoroMinutes} 分钟。
5. 预计超过 2 个番茄钟的任务必须继续拆分。
6. 任务必须按照依赖关系和建议执行顺序排列。
7. 简单目标不要为了增加数量而生成没有必要的任务。
8. 复杂目标只拆解当前阶段，最多生成 8 个微任务。

# 任务计划字段

## goal

用一句话说明本轮任务计划最终要达到的目标。

要求：

- 内容具体、明确。
- 不要简单重复用户原文。
- 不要加入用户没有提供的关键事实。

## assumptions

列出拆解过程中采用的必要假设。

要求：

- 每项假设使用一个独立字符串。
- 没有必要假设时返回空列表。
- 不得返回 null。
- 不要把已经明确的信息重复写成假设。

## tasks

按照建议执行顺序返回微任务列表。

要求：

- 至少包含 1 个微任务。
- 最多包含 8 个微任务。
- 每个任务必须有明确产出和完成标准。
- 后一个任务依赖前一个任务时，必须按依赖顺序排列。

每个任务包含以下字段。

### title

简洁的任务名称。

要求：

- 使用明确的动作动词开头。
- 准确描述该任务的主要行动。
- 不要使用“处理一下”“继续学习”等模糊表达。

### action

说明用户在本次任务中具体需要执行什么。

要求：

- 行动必须具体、可执行。
- 只包含一个主要目标。
- 必要时限定阅读数量、资料范围、代码模块或练习数量。

### output

说明任务完成后应当得到什么可观察的结果。

例如可以是笔记、清单、代码、测试结果、设计方案或总结。

### completionCriteria

说明怎样才算完成。

要求：

- 使用能够客观检查的条件。
- 不要使用“基本掌握”“大致完成”等无法判断的表达。

### estimatedMinutes

该任务预计需要的分钟数。

要求：

- 必须是大于 0 的整数。
- 不得超过 2 个番茄钟的总时长。
- 应根据实际工作量估算，不要求恰好等于番茄钟时长。
- 必须与 pomodoroCount 保持一致。

### pomodoroCount

该任务需要的番茄钟数量。

- 只能是 1 或 2。
- estimatedMinutes 不超过 {pomodoroMinutes} 时，应为 1。
- estimatedMinutes 超过 {pomodoroMinutes} 时，应为 2。
- 优先使用 1；只有任务无法合理继续拆分时才使用 2。


## completionSign

说明完成整组任务后，用户将达到什么可以检查的状态。

要求：

- 必须与本轮目标直接相关。
- 不要使用空泛的鼓励性描述。

## firstAction

给出用户现在可以立即执行的最小动作。

要求：

- 必须对应第一个微任务。
- 用户看到后无需继续规划即可开始。
- 内容应当简短、明确、可立即操作。

# 输出限制

1. 所有规定字段都必须提供。
2. 字符串字段不得为空。
3. assumptions 必须是列表，没有内容时返回空列表。
4. tasks 必须是非空列表。
5. 不要返回结构之外的补充说明。
6. 不要输出 Markdown 代码围栏。
7. 不要在结构化结果前后添加寒暄、解释或总结。
